# 星曆資料夾 / Ephemeris folder

把廣播星曆檔放進這個資料夾並上傳到 GitHub 的 main，網站就會自動改用資料夾裡**最新那一天**的星曆，來推算 GPS 與北斗衛星的位置（地球儀、總覽首頁、技術細節頁的範例與動畫）。

## 怎麼更新（自動）

二選一：

- **在 GitHub 網頁上傳：** 打開 repo 的 `ephemeris/` 資料夾 → Add file → Upload files → 拖入檔案 → Commit changes。
- **在本機：** 把檔案放進這個資料夾，提交並推上 main。

上傳後，GitHub Actions 的「Update ephemeris」會自動：

1. 讀取這個資料夾裡所有的星曆檔，挑出最新的一天。
2. 產生 `data/gnss-YYYY-DDD.json`、更新 `data/latest.json`，並刪掉舊的星曆 JSON。
3. 自動提交這些資料，網站隨後更新（通常幾分鐘內）。

進度與結果在 repo 的 **Actions** 分頁。想改用某一天：Actions → Update ephemeris → Run workflow，填入日期（YYYY-MM-DD）。

## 可以放什麼

- RINEX 3 或 4 的導航檔（navigation），內含 GPS（G）和／或北斗（C）的記錄。
- 一天一個的檔（例如 `BRDM00DLR_S_20253500000_01D_MN.rnx`）、每小時一個的檔（`..._01H_MN.rnx`），或自己接收機輸出的檔都可以。
- 可以是 `.gz` 或 `.zip` 壓縮檔（例如 `BRDC00WRD_S_2026314.zip`，裡面放一整天的每小時檔）；壓縮檔裡可以有資料夾或 `.gz`，不是星曆的檔會略過。
- 可以放在子資料夾；檔名不拘。日期從檔案內容判斷，不看檔名。

## 會怎麼選

- 自動選**最新的一天**。
- 那一天不必是完整 24 小時：只有幾個小時的資料，網站就只在那幾個小時（前後各多 2 小時）內推算與播放。同一天之後再補上更多小時的檔，會自動延長。
- 午夜前後的檔常帶到隔天的一兩筆記錄；只有零星幾顆衛星的日子不會被當成「最新的一天」。
- 只有北斗、沒有 GPS 的日子：地球儀照常更新，技術細節頁跟隨 GPS 衛星的範例則保留內建內容。

## 注意

- 放在這裡的檔案會跟著網站公開（GitHub Pages 會發布整個 repo）。
- 舊的原始檔可以留著，也可以刪掉；只看最新的一天。

## 在本機手動執行（不一定需要）

```bash
node tools/update-ephemeris.js
```

- 指定某一天：`--date 2026-09-22`
- 只看結果、不寫檔：`--dry`
- 刪掉 `data/` 裡舊的星曆 JSON：`--prune`
