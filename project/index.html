雙星座融合訊號

同一個 I/Q 串流裡同時包含 GPS 與北斗訊號，接收機可以一次捕獲兩個系統。

  • 為什麼是這兩個系統：北斗在亞太上空的衛星數量最多，GPS 則是全球最普及的系統；兩者合用，台灣上空可用的衛星大幅增加，定位幾何也更好。
  • GPS L1 C/A：1575.42 MHz，PRN 碼 1.023 Mcps（1023 碼片、週期 1 ms），LNAV 導航電文 50 bps。
  • 北斗 B1I：1561.098 MHz，PRN 碼 2.046 Mcps（2046 碼片、週期 1 ms）；目前支援 MEO／IGSO 的 D1 電文（50 bps，含 NH 二次碼）。
完整說明：06 訊號 ↓

多通道即時並行基頻合成

預設 16 顆衛星的訊號同時計算並疊加（硬體足夠時可再增加），生成速度跟上取樣時鐘，直接串流到 SDR 發射。

  • 通道狀態：每個通道各自維護碼相位、載波相位、都卜勒與導航電文位元，最後累加成一路複數基頻 I/Q。
  • 即時串流：依真實廣播星曆持續計算訊號，連續送入 SDR（UHD）發射。
  • 不能斷流：一旦斷流，真實接收機的鎖相與延遲鎖定迴路就會失鎖。
完整說明：08 發射 ↓

GUI 直接畫出動態路徑

在地圖上畫出路徑，GeoTrust 就沿著它即時產生訊號；不必在命令列載入事先做好的 NMEA 檔。

  • 一般做法：一般 SDR 模擬工具要先寫好 NMEA 檔，把路徑做成符合人走、車行的物理運動，再從命令列載入，反覆修改。
  • GeoTrust：路徑在 GUI 上直接畫出，訊號跟著路徑即時更新。
  • 為什麼重要：動態情境下，定位與欺騙的成功率都比靜態定點高；路徑越容易做，測試就越貼近真實情況。
完整說明：02 起點，在 GUI 設定情境 ↓

異質運算架構：CPU＋GPU

CPU 負責導航與模擬控制，CUDA GPU 加速大量 I/Q 訊號生成。

  • CPU：讀取與篩選 RINEX 星曆、處理時間與座標轉換、計算衛星軌道／時鐘／偽距、挑選可見衛星並更新通道狀態。
  • GPU（CUDA）：平行產生各衛星通道的基頻 I/Q 樣本，再把多通道訊號合成輸出。
  • 其他工作：CPU 也負責 GUI、資料佇列、檔案輸出，以及 USRP 串流管理。

01

欺騙不是假設

從星曆到接收機：把一片天空拆成六站

替接收機做出一片天空，要依序回答六個問題。
接下來六章，一章回答一個。

起點：在 GUI 設定情境

一切從「接收機在哪、怎麼移動」開始。要讓欺騙測試有意義，假訊號必須像真的一樣在動：動態情境下，定位與欺騙的成功率都比靜態定點高。GeoTrust 在 GUI 地圖上直接畫出路徑，六站就沿著它即時算出每一刻的天空。

接著，六站依序算出訊號

跟著 G13 走

接下來每一章都沿用同一個例子：放在高科大的接收機，接收 GPS 衛星 G13。依 2026-09-22 的真實廣播星曆，G13 在台灣時間中午位於高科大上空仰角約 45°，是一顆典型、清楚可見的衛星。

深入了解：詳細說明與公式
  • 硬體：一台具備 NVIDIA GPU（CUDA）的筆電，加上一台 USRP 軟體定義無線電，兩者透過 UHD 驅動連接。
  • 分工：第 1–3 站在 CPU 上執行，邏輯複雜但資料量小；第 4–5 站在 GPU 上執行，每秒要產生數百萬個樣本；第 6 站由 USRP 發射。
  • 可追溯：情境設定與 JSON 紀錄一起保存，之後能以相同條件重新生成同一組訊號。

先看整體：為什麼第一站是時間

  1. 1

    3.1–3.9 km／秒

    位置隨時間改變

    GPS 衛星每秒移動約 3.9 公里；北斗 MEO 約 3.8 公里，IGSO 與 GEO 約 3.1 公里。時間差 1 ms，位置就差約 3–4 公尺。

  2. 2

    BDT = GPST − 14 s

    兩個系統，兩套時間

    GPS 用 GPS 時間，北斗用北斗時間；兩者都不插閏秒，固定相差 14 秒。

  3. 3

    1 條時間軸

    以接收端的樣本為準

    每個樣本都有確定的接收時刻；兩套時間都換到這條軸上，兩個系統才能放進同一個樣本。

再看動畫：一個樣本，推回兩顆衛星的發射時刻

跟著 G13 走

接收端某一個樣本的時刻確定後，往回扣掉 G13 約 72 ms 的飛行時間，就知道 G13 是在什麼時候發出這段訊號；下一站用這個時刻算 G13 的位置。

深入了解：詳細說明與公式
  • 同一條時間軸：各衛星的發射時刻不同，但接收時刻都來自同一個樣本序號，所以 GPS 與北斗混合時不會彼此錯位。
  • 星曆時效：每組廣播星曆都有參考時刻；只採用在有效期間內、狀態健康的那一組。
  • 跨週：跨過週末時，週內秒歸零、週數加一，時間差必須連同週數一起計算。

兩套時間對照

一個樣本的時間

  1. \(t_{\mathrm{rx}} = t_0 + \dfrac{n}{f_s}\)第 n 個樣本的接收時刻：起始時刻加上樣本序號除以取樣率。
  2. \(t_{\mathrm{tx}} = t_{\mathrm{rx}} - \tau\)這顆衛星發出訊號的時刻：接收時刻減去傳播時間。
  3. \(\mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}),\ \delta t(t_{\mathrm{tx}}),\ d(t_{\mathrm{tx}})\)用發射時刻去求衛星位置、時鐘與當下的導航電文位元。

跟著 G13 走

把時刻代進 G13 的星曆，得到它在太空中的位置；從高科大看出去，G13 在仰角 45.2°、正在升起。

深入了解：詳細說明與公式
  • 常數不同：GPS 使用 WGS-84 常數，北斗使用 CGCS2000 常數，地球引力常數與自轉角速度略有差異，必須分開代入。
  • 相對論修正：軌道略有偏心，衛星時鐘會週期性變快變慢，修正量 \(\Delta t_r = F\,e\,\sqrt{A}\,\sin E_k\) 可達數十奈秒，相當於約十公尺的距離。
  • 北斗 GEO：北斗 GEO 衛星的公式另有一次座標旋轉；本平台的訊號目前不含 GEO（見 10 邊界）。

計算步驟（IS-GPS-200／北斗 ICD）

  1. \(A = \left(\sqrt{A}\right)^2,\quad n = \sqrt{\mu / A^3} + \Delta n\)軌道半長軸與平均角速度。
  2. \(t_k = t - t_{oe},\quad M_k = M_0 + n\,t_k\)距星曆參考時刻的時間，以及平近點角。
  3. \(M_k = E_k - e\sin E_k\)克卜勒方程，以疊代求出偏近點角。
  4. \(\nu_k = \operatorname{atan2}\!\left(\sqrt{1-e^2}\,\sin E_k,\ \cos E_k - e\right),\quad \Phi_k = \nu_k + \omega\)真近點角與緯度幅角。
  5. \(\delta u_k = C_{us}\sin 2\Phi_k + C_{uc}\cos 2\Phi_k\)二階諧波修正（半徑與傾角同理）。
  6. \(\Omega_k = \Omega_0 + (\dot{\Omega} - \dot{\Omega}_e)\,t_k - \dot{\Omega}_e\,t_{oe}\)升交點經度，並扣除地球自轉。
  7. \(\mathbf{r}_k = R_3(-\Omega_k)\,R_1(-i_k)\,\begin{bmatrix} x_k^{\prime} & y_k^{\prime} & 0 \end{bmatrix}^{\mathsf{T}}\)旋轉到地球固定座標（ECEF）。
  8. \(\delta t_{\mathrm{sv}} = a_0 + a_1\,\Delta t + a_2\,\Delta t^2 + \Delta t_r - T_{GD}\)衛星時鐘偏差：多項式、相對論項與群延遲。

距離變成時間

訊號以光速前進。GPS 衛星在頭頂時約飛 67 ms，接近地平線時約 84 ms。

衛星與地球都在動

訊號在路上的這段時間，衛星與地球都在移動，所以要用訊號離開那一刻的衛星位置來算距離。

頻率會偏移

衛星靠近時頻率變高、遠離時變低（都卜勒）；靜止的接收機大約在 ±5 kHz 以內。

深入了解：詳細說明與公式
  • 大氣延遲：真實訊號穿過電離層與對流層會多出延遲；目前這些模型與多路徑尚未完整納入（見 10 邊界）。
  • 群延遲：廣播星曆提供的群延遲修正衛星內部硬體的延遲，使模擬的距離與真實衛星一致。
  • 移動接收機：路徑模式下，接收位置隨時間改變，距離與都卜勒同時包含衛星與接收機兩者的運動。

公式

  1. \(\rho = \left\lVert \mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}) - \mathbf{r}_{\mathrm{rx}}(t_{\mathrm{rx}}) \right\rVert\)幾何距離；發射時刻取決於距離，需疊代求解，並加入地球自轉（Sagnac）修正。

天上本來就是同時的

接收機不會一顆一顆輪流收，每個樣本都是所有衛星的總和。

一個通道＝一顆衛星

每個通道記住自己的碼相位、載波相位、頻率與電文位元。

預設 16 個通道

GeoTrust 預設 16 個通道同時計算；硬體夠快時可以再增加。

跟著 G13 走

G13 只是其中一個通道。同一時間，其他看得到的 GPS 與北斗衛星也各占一個通道，在同一個樣本裡和 G13 相加。

可是，GPS 和北斗的頻率不一樣

上面相加的通道裡同時有 GPS 與北斗。GPS 在 1575.42 MHz、北斗在 1561.098 MHz，相差 14.322 MHz。要把兩者放進同一路 I/Q，得先決定它們在基頻的位置。

工程挑戰與解法

兩個星座，同一路 I/Q

  1. 痛點

    GPS L1（1575.42 MHz）與北斗 B1I（1561.098 MHz）相距 14.322 MHz。各用一個射頻通道，就要兩組硬體，還得讓兩路時間對齊。

  2. 選擇

    射頻中心（LO）放在兩者中點 1568.259 MHz；在基頻用數值振盪器（NCO）把 GPS 移到 +7.161 MHz、北斗移到 −7.161 MHz，再相加成一路複數 I/Q。

  3. 結果

    取樣率 20.8 Msps，兩個主瓣都在頻寬內；複數 I/Q 分得出正負頻率，兩邊不會互相折疊。一個發射通道，同時送出兩個星座。

深入了解：詳細說明與公式
  • 為什麼這樣分工：導航計算每 1 ms 只需更新少量參數，邏輯複雜但資料量小，適合 CPU；I/Q 樣本每秒數百萬到數千萬筆且彼此獨立，適合 GPU 平行處理。
  • 資料佇列：CPU 送出各通道參數，GPU 回傳 I/Q 區塊，兩端以佇列銜接、彼此不互相等待。
  • 振幅定標：多路訊號疊加會提高峰值，需控制振幅，避免數值溢位或量化不足。

每個通道每 1 ms 更新的狀態

狀態來源作用
碼相位傳播時間PRN 碼從哪一個碼片開始
碼速率碼都卜勒每個樣本前進多少碼片
載波頻率載波都卜勒每個樣本的相位增量
載波相位累積的頻率區塊之間相位連續

I/Q 樣本的計算

  1. \(s[n] = \sum_{k} A_k\, d_k[n]\, c_k[n]\, e^{\,j\left(2\pi f_{D,k}\, n / f_s + \varphi_k\right)}\)第 n 個樣本：每個通道 k 的振幅 × 電文 × PRN 碼 × 旋轉的載波，全部相加。
  2. \(I[n] = \operatorname{Re}\{s[n]\},\quad Q[n] = \operatorname{Im}\{s[n]\}\)I 是實部、Q 是虛部；一組 (I, Q) 就是一個樣本。

一秒有 1,000 個區塊，合計約 3.33 億次（332,800 × 1,000）；而且每一個區塊都必須在它的 1 ms 內算完。

怎麼分工：CPU 算「在哪」，GPU 算「訊號」，SDR 負責「發射」

工程挑戰與解法

不讓 SDR 有一刻沒資料

  1. 痛點

    USB／PCIe 傳輸與運算時間都會抖動。SDR 的發射緩衝只要見底一次（underrun，UHD 回報「U」），訊號就中斷，接收機的追蹤迴路立刻失鎖。

  2. 選擇

    非同步管線：CPU 計算下一區塊的衛星幾何時，GPU 以 CUDA Streams 合成目前區塊的 I/Q；完成的區塊排進環狀緩衝（Ring Buffer），由 UHD 驅動連續取走。

  3. 結果

    運算的小幅波動由緩衝吸收，端到端延遲維持在 0.1 秒以內，發射不斷流。

工程挑戰與解法

每 1 ms 換參數，波形卻不能有接縫

  1. 痛點

    衛星參數每 1 ms 更新一次。若每個區塊都從零開始算相位，交界處就會跳變，接收機的鎖相迴路會發生週跳（cycle slip），甚至失鎖。

  2. 選擇

    區塊長度對齊 C/A 與 B1I 碼週期（1 ms），每塊計算量固定、GPU 排程穩定；每個通道跨區塊時繼承上一塊結尾的碼相位與載波相位，只更新頻率。

  3. 結果

    參數每 1 ms 更新，波形在時間軸上仍然連續，接收機看不出區塊的存在。

跟著 G13 走

包含 G13 在內的所有衛星訊號，每 1 ms 打包成一個區塊，由 GPU 算好、經緩衝準時送進 SDR 發射，中間不能斷。

深入了解：詳細說明與公式
  • 區塊對齊：區塊長度與 C/A、B1I 碼週期相同（1 ms），碼相位與導航位元邊界自然對齊。
  • 即時計算：每個樣本都依真實星曆即時算出，串流途中仍可改變接收位置與路徑。
  • 緩衝耗盡：一旦緩衝耗盡（underflow），訊號中斷，接收機的鎖相與延遲鎖定迴路就會失鎖。

跟著 G13 走

接收機用 G13 的 PRN 碼找到 G13、持續追蹤，再和其他衛星一起解出位置；最後把結果和模擬設定比對。

工程挑戰與解法

可控的偏差注入，檢驗接收機的防禦

  1. 痛點

    只會產生「正確」的訊號，回答不了接收機遇到異常時會不會察覺。欺騙與故障偵測需要可重複、可量化的測試情境。

  2. 選擇

    以傳導方式（纜線直連，不對空發射）輸入接收機，由軟體動態調整特定衛星的偽距、訊號強度（C/N0），或注入鐘差漂移。

  3. 結果

    檢驗接收機內部的韌性邏輯，例如 RAIM 殘差偵測與都卜勒一致性檢驗，能否主動找出異常衛星並剔除；每次測試都附上紀錄。

深入了解：詳細說明與公式
  • 紀錄要求：每份成果都要附上測試日期、程式版本、硬體與驅動、星曆來源、時間與路徑、取樣率、通道數、I/Q 格式、原始日誌與判定標準。
  • 判定方式：接收機解出的位置與時間，要和模擬設定的軌跡與時刻一致，才算通過。
  • 證據原則：未附測試紀錄的項目不標示為通過；教學動畫不作為定位性能的證據。
