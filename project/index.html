GeoTrust 專案總覽

在實驗室裡，用可重現的數位訊號重建 GPS 與北斗的天空，讓接收機研究可以被重現、被比較、被驗證。

01

為什麼需要 GeoTrust

真實天空無法重來一次。要嚴謹地測試接收機，需要一個可以控制、可以重播的訊號來源。

戶外實測難以重現

天氣、遮蔽、多路徑與衛星位置每次都不同，同一個演算法很難在相同條件下比較兩次。

真實衛星無法控制

無法指定可見衛星數量、移動路徑，或刻意製造異常情境來檢驗接收機的反應。

GeoTrust 讓天空可控

相同的星曆、時間與路徑可以重新生成同一組訊號，並即時調整情境，讓測試可重現、可比較。

03

一顆衛星的訊號長什麼樣子

導航訊號是三層結構相乘：慢速的導航資料、快速的測距碼，以及承載兩者的載波。切換分頁觀察每一層。

50 bps · 每位元 20 ms

導航資料

導航電文以每秒 50 位元播送，內容包含星曆、時鐘修正與時間資訊。圖中高低代表 ±1 的位元符號。

1.023 / 2.046 Mcps · 週期 1 ms

測距碼

每顆衛星有專屬的偽隨機碼。接收機以相關運算找出碼的起點，得到訊號延遲，進而換算距離。

L1 1575.42 · B1I 1561.098 MHz

載波

資料與碼決定訊號的正負號，載波以連續相位承載它們；衛星運動造成的都卜勒會讓頻率略為偏移。

多衛星疊加

合成 I/Q

每個通道各自產生訊號後，在同一時刻相加成一路複數基頻 I/Q。真實的單一衛星訊號遠低於雜訊，需要相關運算才能取出。

示意波形：時間軸經過縮放，非實測訊號。

04

異質運算架構：CPU 結合 GPU

CPU 負責導航與模擬控制，CUDA GPU 加速大量 I/Q 訊號生成；兩者以資料佇列銜接，分工各自擅長的工作。

CPU導航與控制

  1. 讀取與篩選 RINEX 星曆
  2. 時間與座標轉換
  3. 軌道、時鐘與偽距計算
  4. 挑選可見衛星、更新通道狀態
通道參數

GPUCUDA 平行生成

16 個通道同時計算碼、載波與電文，累加為一路 I/Q。

05

1 ms 區塊，即時串流

每 1 ms 產生一個 I/Q 區塊並推入發射緩衝。只要生成速度持續快於取樣時鐘，緩衝就不會耗盡，接收機的追蹤迴路便能保持鎖定。

GPU
發射緩衝
SDR
GPS 最低取樣率設定2.6 Msps單一星座 L1 C/A
北斗最低取樣率設定5.2 Msps單一星座 B1I
混合模式最低取樣率設定20.8 Msps同時涵蓋兩個載波
  • 區塊長度與 C/A、B1I 碼週期相同（1 ms），碼相位與導航位元邊界自然對齊。
  • 與「離線產生檔案再回放」不同，路徑與情境可以在播放中即時改變。
  • 一旦緩衝耗盡（underflow），訊號會中斷，真實接收機的鎖相與延遲鎖定迴路就會失鎖。

取樣率為平台設定值，不是所有接收機的通用最低需求。

06

驗證層級與應用

成果要能回到測試條件、程式版本與原始紀錄。四個層級由內而外，逐步確認訊號正確，再交給獨立接收機檢驗。

01

單元

星曆、時間、座標與碼向量

02

一致性

發射時間、相位、偽距率與樣本數

03

系統

固定點／路徑、單星座／混合輸出

04

外部

獨立接收機捕獲、追蹤與定位

接收機韌性驗證

在受控環境中重現異常或不一致的訊號情境，觀察接收機能否察覺並維持可靠定位。

演算法開發

以已知條件產生的 I/Q 檢查捕獲、追蹤與定位解算流程。

重播與比較

相同設定可再次生成，讓不同版本在同一條件下對照。

教學與人才培育

從軌道、傳播到編碼，逐步拆解導航訊號。

07

目前的研究邊界

清楚標示尚未完成的部分，展示成果時才不會超出實際能力。

  • 北斗目前聚焦 MEO／IGSO 的 B1I-D1，尚未支援 GEO／D2。
  • GPS 與北斗子幀 4–5 仍為最小內容。
  • GPS 專屬電離層係數、對流層與多路徑模型尚未完整納入。
  • 正式的 GPU 效能基準測試尚待完成。
