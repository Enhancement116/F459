雙星座融合訊號

同一個 I/Q 串流裡同時包含 GPS 與北斗訊號，接收機可以一次捕獲兩個系統。

  • 為什麼是這兩個系統：北斗在亞太上空的衛星數量最多，GPS 則是全球最普及的系統；兩者合用，台灣上空可用的衛星大幅增加，定位幾何也更好。
  • GPS L1 C/A：1575.42 MHz，PRN 碼 1.023 Mcps（1023 碼片、週期 1 ms），LNAV 導航電文 50 bps。
  • 北斗 B1I：1561.098 MHz，PRN 碼 2.046 Mcps（2046 碼片、週期 1 ms）；目前支援 MEO／IGSO 的 D1 電文（50 bps，含 NH 二次碼）。
完整說明：06 訊號 →

多通道即時並行基頻合成

預設 16 顆衛星的訊號同時計算並疊加（硬體足夠時可再增加），生成速度跟上取樣時鐘，直接串流到 SDR 發射。

  • 通道狀態：每個通道各自維護碼相位、載波相位、都卜勒與導航電文位元，最後累加成一路複數基頻 I/Q。
  • 即時串流：依真實廣播星曆持續計算訊號，連續送入 SDR（UHD）發射。
  • 不能斷流：一旦斷流，真實接收機的鎖相與延遲鎖定迴路就會失鎖。
完整說明：08 發射 →

1 ms 碼同步生成區塊

GPS C/A 與北斗 B1I 的 PRN 碼週期剛好都是 1 ms，因此以 1 ms 作為生成單位。

  • 碼週期對齊：每個區塊都包含完整的碼週期，碼相位與累加邊界自然對齊。
  • 逐區塊更新：每個區塊開始時更新衛星位置、傳播延遲與都卜勒，再一次產生該區塊的所有樣本。
  • 位元對齊：一個 50 bps 導航位元長 20 ms，正好是 20 個區塊，位元邊界與區塊對齊。
完整說明：08 發射 →

異質運算架構：CPU＋GPU

CPU 負責導航與模擬控制，CUDA GPU 加速大量 I/Q 訊號生成。

  • CPU：讀取與篩選 RINEX 星曆、處理時間與座標轉換、計算衛星軌道／時鐘／偽距、挑選可見衛星並更新通道狀態。
  • GPU（CUDA）：平行產生各衛星通道的基頻 I/Q 樣本，再把多通道訊號合成輸出。
  • 其他工作：CPU 也負責 GUI、資料佇列、檔案輸出，以及 USRP 串流管理。

01

為什麼要把天空搬進實驗室？

重點真實天空每次都不同；GeoTrust 以真實廣播星曆重建衛星訊號，讓同一片天空能可控地重現。

戶外實測難以重現

天氣、遮蔽、多路徑與衛星位置每次都不同，同一個演算法很難在相同條件下比較兩次。

真實衛星無法控制

無法指定可見衛星數量、移動路徑，或刻意製造異常情境來檢驗接收機的反應。

GeoTrust 讓天空可控

以真實廣播星曆重建衛星訊號，可指定接收位置與路徑；相同設定可重新生成，讓測試可重現、可比較。

GeoTrust 站在哪裡

用最少的設備做到

傳統硬體模擬器支援的星系與頻點更多，但仰賴專用的訊號產生硬體。GeoTrust 只用一台筆電與一台 SDR，在 GPS 與北斗上提供即時、可控、可重現的訊號。

軟體控制硬體

訊號完全由軟體算出，SDR 只負責把數字轉成電波；接收位置、時間、路徑與通道數，都在軟體裡設定。

為什麼是 GPS 與北斗

北斗在亞太上空的衛星數量最多，GPS 則是全球最普及的系統。兩者合用，台灣上空可用的衛星大幅增加，也是本地接收機最常同時使用的組合。

深入了解：技術細節
  • 可重現：記錄星曆版本、起始時刻、移動路徑、取樣率與通道數，就能重新生成同一組 I/Q。
  • 可控：可以指定觀測地點、時段與路徑，甚至在播放中即時改變情境，這是戶外實測做不到的。
  • 可比較：不同接收機或不同演算法版本，可以在完全相同的訊號下對照結果。

GPS 與北斗的時間怎麼對齊？

重點兩個系統各有一套時鐘；GeoTrust 以接收端的取樣為準，把兩者放到同一條時間軸上，所有衛星才會同步。

兩套時鐘

GPS 和北斗各自計時，起點不同；北斗時間固定比 GPS 時間少 14 秒。

一條共同的時間軸

GeoTrust 以接收端的取樣為準：每一個樣本都有一個確定的接收時刻。

往回推發射時刻

訊號在路上要飛一段時間，接收時刻減掉飛行時間，就是衛星發出這段訊號的時刻。

跟著 G13 走

接收端某一個樣本的時刻確定後，往回扣掉 G13 的飛行時間，就知道 G13 是在什麼時候發出這段訊號。

深入了解：技術細節
  • 同一條時間軸：各衛星的發射時刻不同，但接收時刻都來自同一個樣本序號，所以 GPS 與北斗混合時不會彼此錯位。
  • 星曆時效：每組廣播星曆都有參考時刻；只採用在有效期間內、狀態健康的那一組。
  • 跨週：跨過週末時，週內秒歸零、週數加一，時間差必須連同週數一起計算。

一個樣本的時間

  1. \(t_{\mathrm{rx}} = t_0 + \dfrac{n}{f_s}\)第 n 個樣本的接收時刻：起始時刻加上樣本序號除以取樣率。
  2. \(t_{\mathrm{tx}} = t_{\mathrm{rx}} - \tau\)這顆衛星發出訊號的時刻：接收時刻減去傳播時間。
  3. \(\mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}),\ \delta t(t_{\mathrm{tx}}),\ d(t_{\mathrm{tx}})\)用發射時刻去求衛星位置、時鐘與當下的導航電文位元。

星曆是一份軌道說明書

廣播星曆是一組描述軌道大小、形狀、方向與時鐘的參數，每隔一段時間更新。

代入公式算位置

知道時間後，依 GPS 與北斗官方規格的公式一步步換算，就得到衛星在太空中的位置。

時鐘也要修正

衛星時鐘並不完美；星曆同時提供修正量，讓模擬出的時間與真實衛星一致。

跟著 G13 走

把剛才得到的發射時刻代入 G13 的星曆，就得到 G13 那一刻在太空中的位置，以及它的時鐘誤差。

深入了解：技術細節
  • 常數不同：GPS 使用 WGS-84 常數，北斗使用 CGCS2000 常數，地球引力常數與自轉角速度略有差異，必須分開代入。
  • 相對論修正：軌道略有偏心，衛星時鐘會週期性變快變慢，修正量 \(\Delta t_r = F\,e\,\sqrt{A}\,\sin E_k\) 可達數十奈秒，相當於約十公尺的距離。
  • 北斗 GEO：北斗 GEO 衛星的公式另有一次座標旋轉；本平台的訊號目前不含 GEO（見 10 邊界）。

計算步驟（IS-GPS-200／北斗 ICD）

  1. \(A = \left(\sqrt{A}\right)^2,\quad n = \sqrt{\mu / A^3} + \Delta n\)軌道半長軸與平均角速度。
  2. \(t_k = t - t_{oe},\quad M_k = M_0 + n\,t_k\)距星曆參考時刻的時間，以及平近點角。
  3. \(M_k = E_k - e\sin E_k\)克卜勒方程，以疊代求出偏近點角。
  4. \(\nu_k = \operatorname{atan2}\!\left(\sqrt{1-e^2}\,\sin E_k,\ \cos E_k - e\right),\quad \Phi_k = \nu_k + \omega\)真近點角與緯度幅角。
  5. \(\delta u_k = C_{us}\sin 2\Phi_k + C_{uc}\cos 2\Phi_k\)二階諧波修正（半徑與傾角同理）。
  6. \(\Omega_k = \Omega_0 + (\dot{\Omega} - \dot{\Omega}_e)\,t_k - \dot{\Omega}_e\,t_{oe}\)升交點經度，並扣除地球自轉。
  7. \(\mathbf{r}_k = R_3(-\Omega_k)\,R_1(-i_k)\,\begin{bmatrix} x_k^{\prime} & y_k^{\prime} & 0 \end{bmatrix}^{\mathsf{T}}\)旋轉到地球固定座標（ECEF）。
  8. \(\delta t_{\mathrm{sv}} = a_0 + a_1\,\Delta t + a_2\,\Delta t^2 + \Delta t_r - T_{GD}\)衛星時鐘偏差：多項式、相對論項與群延遲。

訊號從衛星到接收機，發生了什麼？

重點衛星越遠，訊號越晚到；衛星靠近或遠離，頻率就會偏高或偏低。這兩件事都要寫進每顆衛星的訊號裡。

距離變成時間

訊號以光速前進。GPS 衛星在頭頂時約飛 67 ms，接近地平線時約 84 ms。

衛星與地球都在動

訊號在路上的這段時間，衛星與地球都在移動，所以要用訊號離開那一刻的衛星位置來算距離。

頻率會偏移

衛星靠近時頻率變高、遠離時變低（都卜勒）；靜止的接收機大約在 ±5 kHz 以內。

跟著 G13 走

2026-09-22 台灣時間中午，G13 在仰角 45.2°：距離 21,641 km，訊號要飛 72.2 ms；它正在升起、往接收機靠近，所以頻率略為偏高。

深入了解：技術細節
  • 大氣延遲：真實訊號穿過電離層與對流層會多出延遲；目前這些模型與多路徑尚未完整納入（見 10 邊界）。
  • 群延遲：廣播星曆提供的群延遲修正衛星內部硬體的延遲，使模擬的距離與真實衛星一致。
  • 移動接收機：路徑模式下，接收位置隨時間改變，距離與都卜勒同時包含衛星與接收機兩者的運動。

公式

  1. \(\rho = \left\lVert \mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}) - \mathbf{r}_{\mathrm{rx}}(t_{\mathrm{rx}}) \right\rVert\)幾何距離；發射時刻取決於距離，需疊代求解，並加入地球自轉（Sagnac）修正。
  2. \(\tau = \dfrac{\rho}{c}\)傳播時間，決定 PRN 碼從哪一個碼片開始。
  3. \(f_D = -\dfrac{1}{\lambda}\dfrac{d\rho}{dt}\)載波都卜勒；GPS L1 的 λ ≈ 19.0 cm，北斗 B1I ≈ 19.2 cm。
  4. \(f_{D,\mathrm{code}} = f_D\,\dfrac{f_{\mathrm{chip}}}{f_{\mathrm{carrier}}}\)碼都卜勒：GPS 為載波都卜勒的 1/1540，北斗 B1I 為 1/763。

一顆衛星的訊號長什麼樣？

載波

資料與碼決定訊號的正負號，載波以連續相位承載它們；衛星運動造成的都卜勒會讓頻率略為偏移。

多衛星疊加

合成 I/Q

每顆衛星的訊號在同一時刻相加成一路 I/Q。單一衛星的訊號其實比雜訊還弱，接收機要靠 PRN 碼比對才找得出來。

示意波形：時間軸經過縮放，非實測訊號。

跟著 G13 走

G13 有自己專屬的 PRN 碼。把 G13 的導航電文乘上這組碼，再放到載波上，就是 G13 的訊號；上一章算出的延遲與都卜勒，決定碼從哪裡開始、載波轉多快。

深入了解：技術細節
  • 訊號很弱：GPS L1 C/A 在地面的規格最低接收功率約 −128.5 dBm，低於熱雜訊，必須靠相關運算長時間累積才能取出。
  • 兩系統差異：GPS C/A 碼 1023 碼片、北斗 B1I 碼 2046 碼片，週期都是 1 ms；北斗 D1 電文另外疊加 NH 二次碼。
  • 都卜勒：衛星與接收機的相對速度可達每秒數百公尺，L1 載波因此偏移約 ±5 kHz 以內，碼速率也會同比例微調。

為什麼要同時算？又怎麼同時算？

重點接收機在同一瞬間收到所有衛星，而且每 1 ms 就要交出一段訊號；所以 GeoTrust 讓 GPU 同時計算所有衛星，CPU 負責算衛星在哪。

為什麼要同時算

天上本來就是同時的

接收機在同一瞬間收到所有衛星，所以每一個樣本，都必須同時包含每一顆衛星的訊號。

每段只有 1 ms

即時發射要求每 1 ms 的資料在 1 ms 內算完。混合模式下每 1 ms 有 20,800 個樣本，以預設 16 個通道計，就是約 33 萬次通道運算。

GPU 讓即時可行

一顆一顆輪流算，衛星越多就越慢；GPU 有大量運算核心，可以讓所有通道同時計算，即時發射才有餘裕。

深入了解：技術細節
  • 為什麼這樣分工：導航計算每 1 ms 只需更新少量參數，邏輯複雜但資料量小，適合 CPU；I/Q 樣本每秒數百萬到數千萬筆且彼此獨立，適合 GPU 平行處理。
  • 資料佇列：CPU 送出各通道參數，GPU 回傳 I/Q 區塊，兩端以佇列銜接、彼此不互相等待。
  • 振幅定標：多路訊號疊加會提高峰值，需控制振幅，避免數值溢位或量化不足。

為什麼即時很重要

接收機要連續的訊號

真實接收機一旦斷訊就會失鎖，訊號必須一段接一段、毫不中斷地送出。

情境可以即時改變

每個樣本都即時算出，串流途中仍能改變接收位置與路徑，接收機會像在真實環境中一樣反應。

一般硬體就做得到

靠 GPU 平行計算，一台筆電就能跟上 SDR 的取樣時鐘，不需要專用的訊號產生設備。

時間預算

每 1 ms 的資料都必須在 1 ms 內算完並送出；混合模式下，每 1 ms 有 20,800 個樣本。

發射緩衝

先存放幾段已算好的資料，吸收運算時間的小幅波動，SDR 才能連續發射。

混合模式

GPS 與北斗的頻率相距 14.322 MHz，同一路 I/Q 要同時涵蓋兩者，取樣率因此較高。

跟著 G13 走

包含 G13 在內的所有衛星訊號，每 1 ms 打包成一個區塊，準時送進 SDR 發射，中間不能斷。

深入了解：技術細節
  • 區塊對齊：區塊長度與 C/A、B1I 碼週期相同（1 ms），碼相位與導航位元邊界自然對齊。
  • 即時計算：每個樣本都依真實星曆即時算出，串流途中仍可改變接收位置與路徑。
  • 緩衝耗盡：一旦緩衝耗盡（underflow），訊號中斷，接收機的鎖相與延遲鎖定迴路就會失鎖。

深入了解：技術細節
  • 紀錄要求：每份成果都要附上測試日期、程式版本、硬體與驅動、星曆來源、時間與路徑、取樣率、通道數、I/Q 格式、原始日誌與判定標準。
  • 判定方式：接收機解出的位置與時間，要和模擬設定的軌跡與時刻一致，才算通過。
  • 證據原則：未附測試紀錄的項目不標示為通過；教學動畫不作為定位性能的證據。
