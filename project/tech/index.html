01 · 什麼時候發出

時刻

手機用時間差來量距離，所以四件事都從時刻開始：
從收到的時刻往回推，求出這段訊號是什麼時候發出的。

下一章：軌道 ↓

為什麼從時刻開始

  1. 1

    3.9 km／秒

    衛星一直在動

    GPS 衛星每秒移動約 3.9 公里，北斗 MEO 約 3.8 公里。時間差 1 ms，位置就差約 4 公尺；差 1 秒，就差約 4 公里。

  2. 2

    約 72 ms

    收到的，是過去送出的

    訊號飛到地面要幾十毫秒。此刻收到的樣本，是衛星約 72 ms 前送出的，所以要用「發出時刻」去算衛星位置。

  3. 3

    14 s

    兩套時鐘差 14 秒

    GPS 用 GPS 時間，北斗用北斗時間，固定相差 14 秒（BDT = GPST − 14 s）。忘了換算，北斗衛星會被放到約 53 公里外。

跟著一顆衛星走

手機此刻收到的訊號，是這顆衛星約 72 ms 前發出的。從收到的時刻往回扣掉飛行時間，就是發出的時刻；下一章用它算出衛星當時在哪。

深入了解：詳細說明與公式
  • 同一條時間軸：各衛星的發射時刻不同，但接收時刻都來自同一個樣本序號，所以 GPS 與北斗混合時不會彼此錯位。
  • 星曆時效：每組廣播星曆都有參考時刻；只採用在有效期間內、狀態健康的那一組。
  • 跨週：跨過週末時，週內秒歸零、週數加一，時間差必須連同週數一起計算。

一個樣本的時間

  1. \(t_{\mathrm{rx}} = t_0 + \dfrac{n}{f_s}\)第 n 個樣本的接收時刻：起始時刻加上樣本序號除以取樣率。
  2. \(t_{\mathrm{tx}} = t_{\mathrm{rx}} - \tau\)這顆衛星發出訊號的時刻：接收時刻減去傳播時間。
  3. \(\mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}),\ \delta t(t_{\mathrm{tx}}),\ d(t_{\mathrm{tx}})\)用發射時刻去求衛星位置、時鐘與當下的導航電文位元。

02 · 衛星在哪

軌道

衛星廣播自己的軌道參數，稱為星曆。
把上一章求出的發出時刻代入星曆，就得到衛星當時的位置。

第二步 ／ 共六步

  1. 時刻
  2. 軌道
  3. 傳播
  4. 波形
  5. 合成
  6. 即時
下一章：傳播 ↓
  1. 1

    十幾個參數

    星曆：軌道的說明書

    描述軌道的大小、形狀、傾角與方向。一組星曆約 1–2 小時內保持新鮮，衛星每小時都會廣播。

  2. 2

    代入 t

    參數不變，時間在變

    同一組參數代入不同的時間，就得到不同的位置；所以畫面上參數不動，座標卻一直在變。

  3. 3

    方位・仰角

    換成看得到的天空

    從接收機位置看出去，得到方位與仰角，也就知道哪些衛星在地平線上、能被收到。

跟著一顆衛星走

把時刻代進這顆衛星的星曆，得到它在太空中的位置；從高科大看出去，它在仰角 45.2°、正在升起。

深入了解：詳細說明與公式
  • 常數不同：GPS 使用 WGS-84 常數，北斗使用 CGCS2000 常數，地球引力常數與自轉角速度略有差異，必須分開代入。
  • 相對論修正：軌道略有偏心，衛星時鐘會週期性變快變慢，修正量 \(\Delta t_r = F\,e\,\sqrt{A}\,\sin E_k\) 可達數十奈秒，相當於約十公尺的距離。
  • 北斗 GEO：北斗 GEO 衛星的公式另有一次座標旋轉；本平台的訊號目前不含 GEO（見 08 邊界）。

計算步驟（IS-GPS-200／北斗 ICD）

  1. \(A = \left(\sqrt{A}\right)^2,\quad n = \sqrt{\mu / A^3} + \Delta n\)軌道半長軸與平均角速度。
  2. \(t_k = t - t_{oe},\quad M_k = M_0 + n\,t_k\)距星曆參考時刻的時間，以及平近點角。
  3. \(M_k = E_k - e\sin E_k\)克卜勒方程，以疊代求出偏近點角。
  4. \(\nu_k = \operatorname{atan2}\!\left(\sqrt{1-e^2}\,\sin E_k,\ \cos E_k - e\right),\quad \Phi_k = \nu_k + \omega\)真近點角與緯度幅角。
  5. \(\delta u_k = C_{us}\sin 2\Phi_k + C_{uc}\cos 2\Phi_k\)二階諧波修正（半徑與傾角同理）。
  6. \(\Omega_k = \Omega_0 + (\dot{\Omega} - \dot{\Omega}_e)\,t_k - \dot{\Omega}_e\,t_{oe}\)升交點經度，並扣除地球自轉。
  7. \(\mathbf{r}_k = R_3(-\Omega_k)\,R_1(-i_k)\,\begin{bmatrix} x_k^{\prime} & y_k^{\prime} & 0 \end{bmatrix}^{\mathsf{T}}\)旋轉到地球固定座標（ECEF）。
  8. \(\delta t_{\mathrm{sv}} = a_0 + a_1\,\Delta t + a_2\,\Delta t^2 + \Delta t_r - T_{GD}\)衛星時鐘偏差：多項式、相對論項與群延遲。

03 · 飛了多久

傳播

衛星和手機的位置都確定之後，距離除以光速，就是訊號的飛行時間。
衛星同時在靠近或遠離，頻率也會跟著偏移。

下一章：波形 ↓
  1. 1

    τ = ρ ⁄ c

    距離變成時間

    GPS 衛星在頭頂時約飛 67 ms，接近地平線時約 84 ms；衛星越低，距離越遠，訊號越晚到。

  2. 2

    Sagnac

    用發射那一刻的位置

    訊號在路上的幾十毫秒內，衛星與地球都在動；距離要用發射時刻的衛星位置，並修正地球自轉。

  3. 3

    ±5 kHz

    靠近變高、遠離變低

    衛星靠近時頻率偏高、遠離時偏低（都卜勒）。固定的接收機大約在 ±5 kHz 以內：升起時為正，落下時為負。

為什麼 GPS 和北斗飛的時間不同

兩個系統的軌道高度不同，是設計目的不同：GPS 要全球均勻覆蓋，北斗另外加上停留在亞太上空的高軌道衛星。軌道越高，訊號飛得越久：北斗 IGSO 衛星在頭頂時就要約 119 ms。

軌道離地高度繞一圈為什麼這樣設計
GPS MEO約 20,200 km約 11 小時 58 分每天同一時間回到同一片天空
北斗 MEO約 21,500 km約 12 小時 53 分7 天繞 13 圈，地面軌跡每 7 天重複
北斗 IGSO約 35,800 km約 23 小時 56 分與地球自轉同步，長時間停留在亞太上空
北斗 GEO約 35,800 km約 23 小時 56 分固定在赤道上空某一點（本平台訊號尚不含 GEO）
跟著一顆衛星走

2026-09-22 台灣時間中午，這顆衛星在仰角 45.2°：距離 21,641 km，訊號要飛 72.2 ms；它正在升起、往接收機靠近，所以頻率略為偏高。

深入了解：詳細說明與公式
  • 大氣延遲：真實訊號穿過電離層與對流層會多出延遲；目前這些模型與多路徑尚未完整納入（見 08 邊界）。
  • 群延遲：廣播星曆提供的群延遲修正衛星內部硬體的延遲，使模擬的距離與真實衛星一致。
  • 移動接收機：路徑模式下，接收位置隨時間改變，距離與都卜勒同時包含衛星與接收機兩者的運動。

公式

  1. \(\rho = \left\lVert \mathbf{r}_{\mathrm{sat}}(t_{\mathrm{tx}}) - \mathbf{r}_{\mathrm{rx}}(t_{\mathrm{rx}}) \right\rVert\)幾何距離；發射時刻取決於距離，需疊代求解，並加入地球自轉（Sagnac）修正。
  2. \(\tau = \dfrac{\rho}{c}\)傳播時間，決定 PRN 碼從哪一個碼片開始。
  3. \(f_D = -\dfrac{1}{\lambda}\dfrac{d\rho}{dt}\)載波都卜勒；GPS L1 的 λ ≈ 19.0 cm，北斗 B1I ≈ 19.2 cm。
  4. \(f_{D,\mathrm{code}} = f_D\,\dfrac{f_{\mathrm{chip}}}{f_{\mathrm{carrier}}}\)碼都卜勒：GPS 為載波都卜勒的 1/1540，北斗 B1I 為 1/763。

跟著一顆衛星走

每顆衛星有自己專屬的 PRN 碼。把這顆衛星的導航電文乘上它的碼，再放到載波上，就是它的訊號；72.2 ms 的延遲決定碼從哪個碼片開始，都卜勒決定載波轉多快。

深入了解：詳細說明與公式
  • 訊號很弱：GPS L1 C/A 在地面的規格最低接收功率約 −128.5 dBm，低於熱雜訊，必須靠相關運算長時間累積才能取出。
  • 兩系統差異：GPS C/A 碼 1023 碼片、北斗 B1I 碼 2046 碼片，週期都是 1 ms；北斗 D1 電文另外疊加 NH 二次碼。
  • 都卜勒：衛星與接收機的相對速度可達每秒數百公尺，L1 載波因此偏移約 ±5 kHz 以內，碼速率也會同比例微調。

下一章：即時 ↓
  1. 1

    Σ

    天上本來就是同時的

    接收機不會一顆一顆輪流收；每個樣本都是所有可見衛星的總和。

  2. 2

    1 通道＝1 顆

    每個通道記住自己的狀態

    碼相位、載波相位、都卜勒與電文位元，各通道分開維護，每 1 ms 更新一次。

  3. 3

    16

    為什麼預設 16 個通道

    定位至少要 4 顆衛星；單一星系同時可見的一般約 8–12 顆，16 個通道足以涵蓋，雙星座時則從可見衛星中選出 16 顆。硬體夠快時可以再增加。

跟著一顆衛星走

這顆衛星只是其中一個通道。同一時間，其他看得到的 GPS 與北斗衛星也各占一個通道，在同一個樣本裡和它相加。

工程挑戰與解法

頻率差 14.322 MHz：分別加總，再合成一路

  1. 痛點

    GPS L1（1575.42 MHz）與北斗 B1I（1561.098 MHz）相距 14.322 MHz。各用一個射頻通道，就要兩組硬體，還得讓兩路時間對齊。

  2. 選擇

    GPS 通道與北斗通道先在基頻各自加總。射頻中心（LO）放在兩者中點 1568.259 MHz，再用數值振盪器（NCO）把 Σ GPS 移到 +7.161 MHz、Σ 北斗移到 −7.161 MHz，相加成一路複數 I/Q。

  3. 結果

    取樣率 20.8 Msps 時兩個主瓣都在頻寬內；複數 I/Q 分得出正負頻率，兩邊不會互相重疊。一台 SDR、一個發射通道，同時送出兩個星座。

深入了解：詳細說明與公式
  • 為什麼這樣分工：導航計算每 1 ms 只需更新少量參數，邏輯複雜但資料量小，適合 CPU；I/Q 樣本每秒數百萬到數千萬筆且彼此獨立，適合 GPU 平行處理。
  • 資料佇列：CPU 送出各通道參數，GPU 回傳 I/Q 區塊，兩端以佇列銜接、彼此不互相等待。
  • 振幅定標：多路訊號疊加會提高峰值，需控制振幅，避免數值溢位或量化不足。

每個通道每 1 ms 更新的狀態

狀態來源作用
碼相位傳播時間PRN 碼從哪一個碼片開始
碼速率碼都卜勒每個樣本前進多少碼片

載波相位累積的頻率區塊之間相位連續

I/Q 樣本的計算

  1. \(s[n] = \sum_{k} A_k\, d_k[n]\, c_k[n]\, e^{\,j\left(2\pi f_{D,k}\, n / f_s + \varphi_k\right)}\)第 n 個樣本：每個通道 k 的振幅 × 電文 × PRN 碼 × 旋轉的載波，全部相加。
  2. \(I[n] = \operatorname{Re}\{s[n]\},\quad Q[n] = \operatorname{Im}\{s[n]\}\)I 是實部、Q 是虛部；一組 (I, Q) 就是一個樣本。

為什麼以 1 ms 為一塊

GPS C/A 碼與北斗 B1I 碼的週期都正好是 1 ms。把訊號切成 1 ms 一塊，每塊剛好裝下整數個碼週期，衛星參數也在區塊交界一起更新。所以「1 ms」指的是每一塊訊號的長度；即時的要求是：算完一塊的時間，要比這一塊的長度短。

每一次都包含碼、載波與電文；一秒要做 1,000 個這樣的區塊，每一塊都要在它的 1 ms 內完成。

怎麼分工：CPU 算「在哪」，GPU 算「訊號」，SDR 負責「輸出」

CPU 負責 01–03 的時刻、軌道與傳播：每 1 ms 只需更新少量參數，邏輯複雜但資料量小。GPU 負責 04–05 的波形與合成：數十萬次彼此獨立的運算，正適合平行。SDR 只負責把算好的樣本輸出。接下來兩個工程挑戰，都是為了讓這條流水線不斷。

工程挑戰與解法

① 區塊之間不能有接縫

  1. 痛點

    衛星參數每 1 ms 更新一次。若每個區塊都從零開始算相位，交界處就會跳變，接收機的鎖相迴路會發生週跳（cycle slip），甚至失鎖。

  2. 選擇

    每個通道跨區塊時，繼承上一塊結尾的碼相位與載波相位，只更新頻率；區塊長度又剛好是碼週期，碼的起點自然對齊。

  3. 結果

    參數每 1 ms 更新，波形在時間軸上仍然連續，接收機看不出區塊的存在。

工程挑戰與解法

② 算好的區塊，要準時交到 SDR

  1. 痛點

    每一塊的計算時間與 USB 傳輸都會小幅抖動，偶爾慢一點。SDR 的緩衝一旦見底（underrun），輸出就中斷，接收機的追蹤迴路會失鎖。

  2. 選擇

    非同步管線：CPU 計算下一區塊的衛星幾何時，GPU 以 CUDA Streams 合成目前區塊的 I/Q；完成的區塊排進環狀緩衝（Ring Buffer），由 UHD 驅動連續取走。

  3. 結果

    運算的小幅波動由緩衝吸收，端到端延遲維持在 0.1 秒以內，發射不斷流。

跟著一顆衛星走

包含這顆衛星在內的所有衛星訊號，每 1 ms 打包成一個區塊，由 GPU 算好、經緩衝準時送進 SDR 輸出，中間不能斷。

跟著一顆衛星走

接收機用這顆衛星的 PRN 碼找到它、持續追蹤，再和其他衛星一起解出位置；最後把結果和模擬設定比對。

工程挑戰與解法

可控的偏差注入，檢驗接收機的防禦

  1. 痛點

    只會產生「正確」的訊號，回答不了接收機遇到異常時會不會察覺。欺騙與故障偵測需要可重複、可量化的測試情境。

  2. 選擇

    以傳導方式（纜線直連，不對空發射）輸入接收機，由軟體動態調整特定衛星的偽距、訊號強度（C/N0），或注入鐘差漂移。

  3. 結果

    檢驗接收機內部的韌性邏輯，例如 RAIM 殘差偵測與都卜勒一致性檢驗，能否主動找出異常衛星並剔除；每次測試都附上紀錄。

深入了解：詳細說明與公式
  • 紀錄要求：每份成果都要附上測試日期、程式版本、硬體與驅動、星曆來源、時間與路徑、取樣率、通道數、I/Q 格式、原始日誌與判定標準。
  • 判定方式：接收機解出的位置與時間，要和模擬設定的軌跡與時刻一致，才算通過。
  • 證據原則：未附測試紀錄的項目不標示為通過；教學動畫不作為定位性能的證據。

雙星座融合訊號

GPS 與北斗各自計算時間、軌道、傳播與訊號，最後合成同一路 I/Q，接收機可以一次捕獲兩個系統。

  • 為什麼是這兩個系統：北斗在亞太上空的衛星數量多，GPS 是全球最普及的系統；兩者合用，台灣上空可用的衛星更多，定位幾何也更好。
  • 兩者的差別：時間差 14 秒、軌道高度不同、頻率差 14.322 MHz、碼長 1023 與 2046 碼片，每一章都分開處理。
完整說明：01 時刻 ↓

異質運算架構：CPU＋GPU

CPU 負責時間、軌道與傳播這類邏輯複雜、資料量小的計算；GPU 負責大量彼此獨立的訊號樣本。

  • CPU：讀取星曆、換算時間與座標、計算軌道與距離、挑選可見衛星，每 1 ms 更新各通道參數。
  • GPU（CUDA）：每 1 ms 要算 20,800 個樣本 × 16 個通道，平行產生後合成一路 I/Q。
完整說明：04 波形 ↓

即時串流發射

訊號邊算邊發：每 1 ms 長的訊號，必須在 1 ms 內算完並交給 SDR，接收機才能邊收邊反應。

  • 不能斷流：緩衝用完之前下一塊沒有趕上，SDR 就沒有資料可輸出，接收機的追蹤迴路會失鎖。
  • 預設 16 通道：足以涵蓋同時可見的衛星；硬體夠快時可以再增加。

即時與非即時的邊界

即時發射時，每 1 ms 的樣本必須在 1 ms 內算完，所以能用多高的取樣率，取決於電腦算得多快，以及 SDR 能收多快，兩者取較小的一個。超過這個邊界時，改用非即時模式：先產生 I/Q 檔，不受 1 ms 的限制，之後再重播。
