01 / INTUITION

產生了訊號，如何知道接收機讀得懂？

有訊號檔案只是起點。驗證要沿著接收機的處理順序，確認它能找到訊號、持續跟上、讀出電文，最後才檢查定位結果。

02 / MECHANISM

把中間的步驟連起來。

  1. 捕獲

    在碼延遲與頻率偏移的搜尋範圍中找候選峰值。

  2. 追蹤

    持續修正碼與載波的估計，建立穩定觀測。

  3. 解碼

    檢查位元、電文框架與時間資訊是否一致。

  4. 定位與評估

    解算位置、速度與時間，再量化誤差與穩定度。

相關峰值表示訊號與本地模型相似，但可能仍有錯峰或頻率偏差。追蹤穩定也不代表電文一定正確；每一關都需要獨立觀察，才知道問題發生在訊號生成、資料內容還是解算端。

探索更多：術語與進階模型訊號 → 捕獲 → 追蹤 → 電文 → PVT

PVT 是位置、速度與時間。應記錄首次定位時間、位置誤差、追蹤中斷及重複測試條件；單次成功定位只支持該次條件下的功能性。

03 / IN GEOTRUST

這一步，在 GeoTrust 裡做什麼？

已知向量 → 相位連續 → 檔案重播 → 獨立接收機

先檢查星曆欄位、PRN 週期與 BCH／同位檢查，再核對每星發射時間、區塊間相位與樣本數。最後用獨立接收機檢查捕獲、追蹤、導航資料與 PVT。產生 I/Q 檔案不等同已通過定位精度測試。

探索更多：從設定到可查證的輸出

輸入：模擬時間、位置或路徑、星曆。中間狀態：每星延遲、碼相位、載波與資料索引。輸出：I/Q 與 JSON。查證時固定版本及輸入，再比較編碼向量、頻譜與接收機結果。
